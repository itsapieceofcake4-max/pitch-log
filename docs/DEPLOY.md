# Pitch Log を別の PC から使う

対象アプリは 2 つある。**データの重さが違うので、扱いも変わる。**

| アプリ | 何を入力にするか | 会社PCから見るには |
|---|---|---|
| **app_25**（ラグビー） | 試合映像（数GB） | 切り出した40秒クリップ（数十MB）をアップロード |
| **app_26**（PFF サッカー） | PFF データセット（数GB・権利あり） | **書き出した CSV（1MB未満）をアップロード** |

どちらも「重い抽出は手元の PC、閲覧はクラウド」という同じ形にしてある。

---

## デプロイは `app_home.py` を指定する（1 つの URL で両方）

Streamlit Community Cloud の**非公開アプリは 1 つまで**。アプリごとに別々に
デプロイすると、限定公開にできるのが 1 つだけになってしまう。

そこで `app_home.py` にまとめてある。これをメインファイルに指定すれば、
**1 つの URL・1 つの非公開枠**で両方使える。

| Streamlit Cloud の設定 | 値 |
|---|---|
| Repository | `itsapieceofcake4-max/pitch-log` |
| Branch | `main` |
| **Main file path** | **`app_home.py`** |

左のメニューで「PFF シーンブラウザ」「ラグビー映像トラッキング」を切り替える。

---

## app_26（PFF）を会社 PC から見る

PFF のデータセットは **数 GB あり、そもそもクラウドに載らない**
（Streamlit Community Cloud はメモリ約 1GB）。加えて、他社のデータセットを
公開リポジトリへ置くのは「使う」ではなく「配る」ことになるため行わない。

一方、書き出した CSV は 1 シーンで 1MB 未満。これだけを持ち出せばよい。

```
自宅PC: PFF実データ ──[app_26 で抽出]──▶ 425指標CSV（779KB）
                                              │
                                        アップロード
                                              ▼
会社PC: ブラウザ ──────▶ クラウドの app_26（CSV読み込みモード）
```

### 手順

1. **自宅 PC**（PFF データがある側）で app_26 を開き、シーンを選ぶ
2. ③タブで `_enriched.csv`（425列）をダウンロード
3. そのファイルを会社 PC へ持ち込む（メール・OneDrive など）
4. **クラウドの app_26** を開き、サイドバーから CSV をアップロード

app_26 は **PFF データが見つからない環境では自動で「CSV 読み込みモード」**に
切り替わる。俯瞰の 2D 表示・425指標の一覧・再ダウンロードはすべて動く。
できないのは「PFF の生データから新しいシーンを切り出すこと」だけ。

> スロット対応表（P1〜P11 が誰か）も一緒に持ち込むと、選手名が表示される。
> 無い場合は P 番号のまま表示される。

# Pitch Log v25 を別の PC から使う

会社 PC などから使うための選択肢と手順。**用途によって最適解が変わる**ので、
まず下の比較を見て決めてください。

---

## どれを選ぶか

| | A. 会社PCにインストール | B. Streamlit Cloud（限定公開） | C. Streamlit Cloud（一般公開） |
|---|---|---|---|
| URL でどこからでも見る | ✗ | ○ | ○ |
| **映像の解析速度** | **速い（フル性能）** | 遅い（共有CPU） | 遅い |
| **長い試合映像** | **そのまま扱える** | アップロード必要・容量制限 | 同左 |
| 映像が外部に出る | **出ない** | 出る | 出る |
| 誰が使えるか | その PC の人 | **招待した人だけ** | **URLを知る全員** |
| 費用 | 無料 | 無料 | 無料 |
| 会社PCの管理者権限 | 必要な場合あり | 不要 | 不要 |

### 推奨

- **実際に解析業務で使う → A（会社PCにインストール）**
  動画処理は重く、長い試合映像を扱います。クラウドの無料枠では速度・容量とも
  厳しく、実運用には向きません。
- **打ち合わせで画面を見せたい・触ってもらいたい → B（限定公開）**
  短いクリップでのデモなら十分動きます。招待した人だけがアクセスできます。
- **C（一般公開）は推奨しません。** 認証が無く、URL を知る誰でも映像を
  アップロードして使えてしまいます。チームの映像を扱う道具としては危険です。

---

## A. 会社 PC にインストールする（推奨）

### 1. Python を入れる
[python.org](https://www.python.org/downloads/) から **3.10 以上**。
インストーラの「Add Python to PATH」に必ずチェックを入れる。

### 2. 取得して起動

```bash
git clone https://github.com/itsapieceofcake4-max/pitch-log.git
cd pitch-log
pip install -r requirements.txt
streamlit run app_25.py
```

git が使えない場合は GitHub の画面から「Code → Download ZIP」で取得しても可。

ブラウザが自動で開きます（開かなければ `http://localhost:8501`）。
止めるときはコマンドプロンプトで `Ctrl + C`。

### 3. うまくいかないとき

| 症状 | 対処 |
|---|---|
| `pip` が見つからない | `python -m pip install -r requirements.txt` |
| 会社PCで pip がブロックされる | 社内プロキシ設定が必要。情シスに確認 |
| ポート 8501 が使用中 | `streamlit run app_25.py --server.port 8600` |
| 起動時にメール入力を求められる | 何も入れずに Enter |

## B. Streamlit Community Cloud に限定公開する

### 事前に確認すること

- リポジトリ `itsapieceofcake4-max/pitch-log` は **public** です。
  ソースコードは誰でも読めます（アプリのアクセス制限とは別の話）。
- `.gitignore` で NDA データ由来の成果物・競合分析・実映像を除外しています。
  **新しいファイルを追加するときは、公開してよいものか必ず確認してください。**

### 手順

1. 変更を push する

   ```bash
   cd pitch-log
   git add -A
   git status          # 意図しないファイルが入っていないか必ず目視
   git commit -m "Add v25 rugby tracking app"
   git push origin main
   ```

2. [share.streamlit.io](https://share.streamlit.io) に GitHub アカウントでサインイン

3. **Create app** → リポジトリ `itsapieceofcake4-max/pitch-log` /
   ブランチ `main` / メインファイル `app_25.py` を指定

4. **Advanced settings** で Python version を **3.11** 以上に

5. Deploy。数分でビルドされ、`https://xxxx.streamlit.app` の URL が出る

6. **アクセス制限をかける（重要）**
   アプリの Settings → **Sharing** →「Only specific people can view this app」を選び、
   会社のメールアドレスを招待する。これで招待した人しか開けません。

### クラウドでの制約

- **フル試合の映像は、そのままではアップロードできません。** 下記「長い試合映像の
  扱い」を参照してください。
- **メモリ約 1GB / 共有 CPU。** 解析速度は手元の PC より大幅に遅くなります。
- **ファイルは保存されません。** アプリが再起動すると消えます。CSV や動画は
  その場でダウンロードしてください。
- **YOLO バックエンドは動きません**（`ultralytics` は既定で入れていません）。
  背景差分のみ使えます。

---

## 長い試合映像の扱い（重要）

ラグビーの試合は 80 分＋で、映像は次の大きさになります。

| 画質 | 試合全体 | 30 秒ぶん |
|---|---|---|
| 1080p 高画質 (8Mbps) | **5.4 GB** | 30 MB |
| 1080p 標準 (4Mbps) | **2.7 GB** | 15 MB |
| 720p (3Mbps) | **2.0 GB** | 11 MB |

Streamlit のアップロードはファイル全体をメモリに載せるため、**GB 級の
ファイルはクラウドでは通りません**。一方で解析に使うのは 30 秒だけなので、
先に切り出せば数十 MB に収まります。

### 切り出しの手順

**アプリの①タブ**で長い映像（2 分超）を読み込むと「この試合から切り出す」欄が
表示されます。見たい場面をプレビューで探し、長さ 40 秒ほどで切り出してください。
そのまま解析対象が切り出したクリップに切り替わります。

コマンドラインからも実行できます。

```bash
python -m rugby.clip --video match.mp4 --start 1830 --duration 40 --out scene.mp4
```

ffmpeg が入っていれば **再エンコードせずほぼ一瞬**で終わります
（実測：10 分・839MB の映像から 30 秒を **0.33 秒** で切り出し、42MB＝元の 5%）。
ffmpeg が無い環境では OpenCV で再エンコードします（遅いが確実）。

### 実際の運用フロー（限定公開の場合）

```
手元PC: 試合映像 ──[rugby.clip で切り出し]──▶ 40秒クリップ（数十MB）
                                                    │
                                            アップロード
                                                    ▼
会社PC: ブラウザ ──────▶ Streamlit Cloud のアプリで解析・CSV取得
```

長い映像を頻繁に見返すなら、**A（会社PCにインストール）のほうが快適**です。
切り出しの手間も要らず、解析も速く終わります。

## C. 一般公開する場合の注意

手順は B と同じで、6 の Sharing を「Anyone with the link」にするだけです。
ただし次を理解したうえで判断してください。

- **認証がありません。** URL を知る誰でも、自分の映像をアップロードして
  解析できます。計算資源も共有されるため、他人の利用で重くなります。
- **アップロードされた映像は Streamlit 社のインフラを経由します。**
  チームの映像・対戦相手の映像を扱う場合、権利や機密の観点から社内確認を
  推奨します。
- 公開をやめたいときは、Streamlit Cloud の Settings からいつでも
  限定公開に戻す、またはアプリを削除できます。

## 補足：クラウド向けの実装上の配慮

- `requirements.txt` は **`opencv-python-headless`** を指定しています。
  GUI 機能（`imshow` 等）を一切使っていないため headless で足り、サーバ側に
  `libGL` などの追加 apt パッケージを入れずに済みます。
- `.streamlit/config.toml` でテーマとアップロード上限を指定しています。
  秘密情報は `.streamlit/secrets.toml`（`.gitignore` 済み）に置いてください。
