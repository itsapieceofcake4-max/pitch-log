# TODO: GSA結果リーダー（将来機能メモ）

## 概要

GSA（因果関係解析システム）の出力を読み込み、
目的変数に対する影響度の大きい順に「**注目すべきプレー**」を整理する機能を追加する。

> ⚠️ GSAシステム本体は機密性が高いため、Pitch Log とは別環境で実行する。  
> Pitch Log は GSA の **出力ファイルを読み込むだけ**の役割。

---

## 要件

### 入力
- GSAが出力する因果マッピング（CSV または JSON を想定）
- 形式は今後 GSA 側と合意して決める

### 処理
目的変数（例：`Delta_Ball_xT` のピーク）に対して、
**因果の階層**を整理する：

```
目的変数 (ゴール直結プレー)
 ├── 1次原因（直接影響）: 因果スコア降順 TOP N
 ├── 2次原因（1次原因を引き起こした要因）: 同上
 └── 3次原因（2次原因を引き起こした要因）: 同上
```

### 出力（イメージ）
```
═══════════════════════════════════════════════════════
🎯 目的変数: Delta_Ball_xT @ Frame 290 (ゴール直前)
═══════════════════════════════════════════════════════

【1次原因 — 直接影響】
  1. Away_P9 のラン (frame 285-290)
     因果スコア: 0.42
     プレー内容: ペナルティエリア背後への飛び出し
     評価理由 : ボールxTが0.08→0.45に急増したタイミングで
                守備ラインを突破している

  2. Away_P7 のスルーパス (frame 285)
     因果スコア: 0.31
     プレー内容: 中央から右サイドへのスルーパス
     評価理由 : Δ Ball_xT のジャンプ直前に発生

【2次原因 — 1次原因を作った要因】
  1. Away_P10 のオフボールラン (frame 270-280)
     因果スコア: 0.18
     プレー内容: 中央への囮ラン
     評価理由 : Home_P5 を引き付け、P9 の突破スペースを創出

  2. Home_P5 (J.O'Shea) のポジショニング (frame 275-285)
     因果スコア: -0.22 (負の貢献 = 守備崩壊)
     プレー内容: 中盤での対応遅れ
     評価理由 : 2次の原因に最も大きく寄与

【3次原因 — 起点・伏線】
  1. Away_P3 のビルドアップパス (frame 250-260)
     因果スコア: 0.11
     プレー内容: 自陣からの縦パス
     評価理由 : 攻撃の起点。ここから連鎖が始まった
```

## 整理の観点

各プレーには以下の2つを必ず含める：

| 観点 | 内容 |
|---|---|
| **どんなプレー** | 客観的なプレー記述（誰が・いつ・何をした） |
| **なぜ評価** | 因果スコアの背景説明（何に貢献したのか） |

## 実装の方向性（今後の検討事項）

### ファイル候補
- `gsa_reader.py` （独立スクリプト）
- または `app_24.py` として GUI 化

### GSA 出力フォーマットの想定（仮）
```csv
target_variable, target_frame, cause_var, cause_frame, causal_strength, layer
Delta_Ball_xT, 290, Away_P9_xT, 285, 0.42, 1
Delta_Ball_xT, 290, Away_P9_speed, 285, 0.31, 1
Away_P9_xT, 285, Away_P10_xT, 275, 0.18, 2
...
```

### プレー記述の自動生成
- 1次/2次/3次のカラム名から、選手・フレーム・指標を抽出
- シーンCSV（Export_GSA_22players_30s_gsa_extended.csv）と突合して
  位置・速度・距離・周囲の状況を補足
- 「ペナルティエリア背後への飛び出し」のような自然言語化は
  ルールベース or LLM活用も検討

### 出力形式
- ターミナル表示
- Markdown レポート（試合分析資料用）
- Streamlit 上のインタラクティブ表示（app_24 として）

## メモ

- GSA 本体は別環境で運用（機密保持）
- Pitch Log 側は「**結果を読み込んで人間に説明する**」役割に専念
- 1次/2次/3次の階層数は柔軟に（GSA出力次第）
- 「報われるべき選手」を可視化することがゴール
  → ゴールやアシスト以外のプレー（オフボール・守備・起点）の評価
