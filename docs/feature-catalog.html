⚠️ 注意：多重共線性

以下のペアは 両方入れない。GSA の因果スコアが分散して正しく出ない。
ペア理由
位置(X,Y) と 個人xTxTは位置から計算される
個人xT と 個人GridIDGridIDも位置の関数
MAX_xT と 個人xT全員MAXは個人xTの集計
SUM_xT と 個人xT全員SUMは個人xTの集計
Ball_speed と Ball_vx/vyspeedは成分から計算
Pressure_on_carrier と n_opp_within_3m for carrier同じ情報

GSA投入時はどちらか片方を選ぶ。

新試合の導入手順

Step 1: トラッキングデータの形式確認

  • 座標系：[0,1] 正規化？ それとも実メートル？
  • FPS：10 / 25 が一般的
  • 原点：左下？中央？
  • 選手番号：固定？ 入れ替わる？
  • Home/Away の振り分け

Step 2: 変換スクリプトを作成

既存の convert_skillcorner_to_pipeline.py を雛形にして、 プロバイダ別の convert_xxx_to_pipeline.py を作る。
出力すべき形式（v22 が期待する CSV）: 

frame, time_sec, ball_x, ball_y, is_goal_frame,
Home_1_x, Home_1_y, ..., Home_11_x, Home_11_y,
Away_1_x, Away_1_y, ..., Away_11_x, Away_11_y

Step 3: パイプライン実行

python xt_pipeline_22.py
python xt_pipeline_23.py --gsa_extend Export_GSA_22players_30s.csv

→ カラム ① 〜 ⑧ ⑩（📍 と 🎯）が自動生成される
→ ⑨ は events データがなければスキップされる

Step 4: GSA 投入

目的変数 (Δ Ball_xT 等) と説明変数 (xT・距離・速度・ラグ) はどの試合でも共通形式。
SkillCorner 由来の VAEP 関連 (⑨) は使えないが、それ以外は問題なく動く。

✅ 結論：トラッキングデータが手に入る試合なら、 カラムカタログの約 9割（450/500 カラム）が自動生成可能。
SkillCorner 専用は カテゴリ⑨のみ。月曜以降の他試合導入も問題ありません。
